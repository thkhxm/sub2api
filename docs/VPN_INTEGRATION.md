# VPN 个人订阅接入

Sub2API 管理平台身份、订阅绑定、余额资格、VPN 用户组及节点分配；每台独立的 VPS VPN 实例运行 Marzban/Xray，负责实际代理、个人用量、每日历史、每月账期和访问控制。本文包含 2026-09-22 的管理增强，发布时平台与节点端须配套升级。

## 使用规则

- 新开通默认每人每月 80 GiB（85899345920 bytes），上海时间每月 22 日 00:00 重置，不结转；月中创建获得完整当期额度。已有 30 GiB 或其他自定义额度在迁移时保持原样。
- 自助申请时事务检查 `users.balance > 0`，不扣费、不冻结。该字段已是可用余额，不能再减 frozen_balance。之后余额为零不自动停用；管理员可以为零余额用户代开。
- 每用户最多一份未删除绑定。创建中、删除中、失败待重试、禁用和超额均占名额；无用户侧删除、转绑或清零入口。管理员删除须经节点确认旧链接、凭据和连接失效后才解除绑定；之后用户满足余额条件即可重新开通，使用新的远端身份和链接。
- 仅向启用、健康、最近两分钟确认可用且有完整月额容量的节点分配。排序依据为“已分配月额度总和 ÷ 节点月额度”；占比相同时按最久未分配、节点 ID 排序。节点月额未配置、额度快照未知或容量不足时不接收新订阅。
- 已分配月额包含节点所有有限额账号，以及平台待开通、增额和迁移目标预占；同一 owner 已在节点生效的部分不会重复计算。暂停、到期但未删除的有限额账号仍占额度，不限量运维账号按零计入。降额和删除未确认前保守保留原额度，实际已用流量不参与此分配占比。
- 节点禁用还会在排队任务实际下发前复核。尚未下发的创建直接改派；已触及旧节点的创建和禁用节点上的凭据轮换，先确认旧身份被撤销，再迁移到启用且健康的节点。没有可用目标或旧节点无法确认撤销时保持待处理，不额外创建第二份可用账号。
- 禁用节点不会自动迁走全部已完成订阅；管理员手动选择目标节点后轮换。选当前健康节点时原地换凭据，不额外占额度；选择其他节点时按完整月额预占并迁移，保留用户组、目标月额和本期已用量。手选目标中途不可用时等待该节点恢复，不会静默换到其他节点。迁移期间不能用新的管理操作覆盖原任务，失败时重试原操作。
- 用户被平台禁用或软删除后，后台排队禁用 VPN；恢复平台用户不会自动恢复 VPN，管理员需重新启用。任何失败显示实际状态，不把数据库状态当成已阻断。

## 管理员配置

1. 先部署包含删除墓碑、每日用量接口和修订 Xray 的 VPS VPN，验证 HTTPS、`TROJAN_TLS`、个人采样和 `/api/integration/server`。旧节点不具备新删除接口，不能先对旧节点执行删除验收。
2. 在「VPN 管理 → 添加节点」填写名称、HTTPS Base URL、接入管理员用户名与密码。私有 CA 环境提供 PEM；公共受信任证书可留空。证书校验始终开启。
3. 节点检测通过且已配置月额后参与自动分配。管理员可搜索平台用户代开，查看汇总、流量、账期、失败原因，调整额度、启停、重试原操作、手选节点轮换、删除订阅、管理 VPN 用户组。订阅列表以进度条展示已用/额度及百分比，支持已用流量升降序，排序在服务端分页前执行。
4. 已绑定用户的节点不能修改 Base URL 迁移到另一个实例。新增实例应新建节点。编辑时密码留空保留原值；CA 字段省略保留，显式空字符串清除。

## 节点运维订阅与 IP 管理

每节点使用安装器指定的独立 `sub2api` 运维账号，不限流量、无到期，不占个人分配人数，但实际传输仍计入节点用量。节点卡片的「运维订阅」可幂等生成或读取 Clash、Base64、sing-box 地址；重复读取不轮换密码或清空用量，账号冲突时返回错误，不覆盖已有账号。

运维入口仅管理员可访问，配置未在 Xray 实际生效前不展示地址，响应禁止缓存。节点的个人分配启停不影响管理员读取运维订阅。平台管理员接口为 `GET/POST /api/v1/admin/vpn/servers/:id/egress`：GET 只读，POST 幂等确保账号存在。

IP 管理接收 HTTP/SOCKS 代理地址，不能直接填入 Trojan 订阅 URL。使用既有宿主代理客户端加载运维身份并提供经过认证的 SOCKS 出口，再将对应主机、端口和凭据配置到 IP 管理；保留独立的默认出站通道和原有账号绑定。应从实际 Sub2API 容器执行代理检测，并核对出口 IP 与目标节点一致。

接入管理员凭据仅由后端保存，复用现有 AES-256-GCM 加密器，密钥来自稳定的 `TOTP_ENCRYPTION_KEY`。本功能不修改生产密钥；备份恢复必须保留原密钥。节点配置、管理响应和日志均不回显密码。登录 JWT 在内存缓存，401 后最多重新登录一次；不继承系统 HTTP 代理，不允许远端重定向。

## VPN 用户组与批量月额

VPN 用户组独立于 AI 服务分组。默认组初始 80 GiB，管理员可以新建组、修改组名称和月额，并调整用户所属组。成员关系跟随平台用户保存，删除订阅后仍保留；重新开通使用当前组月额。

只改组名称不触发额度覆盖。明确修改组月额时，将组内现有订阅的目标额度批量更新；个别订阅的自定义额度会被本次组更新覆盖。切组同样按目标组额度更新，不清除当期已用流量，不更改启停状态。额度小于已用量时由节点执行限额。

批量更新与已有创建、轮换等操作串行生效。处理中显示同步数量，失败保留错误和原操作供重试；旧操作迟到不会覆盖更新后的目标月额。删除中的订阅不再执行额度同步。

## 节点剩余与每日流量

节点卡片展示配置月额、已统计用量、本期补充已用、剩余估算、下次重置、采样时间和历史覆盖起点。月额设为 0 表示未配置。本期补充已用仅对保存时的上海 22 日账期有效，换月自动不计；用于接续迁移前已消耗的流量。

剩余估算为 `max(月额 - 节点所有 VPN 账号本期逻辑流量 - 本期补充已用, 0)`，包含运维账号，不能当作服务商网卡计费账单。未返回遥测、过期或采样缺口时显示未知。`partial_history` 可展示带明确警示的估算，缺失历史可能使剩余值偏高。

2026-09-22 只读核对三台现有旧账期配置：104.194.80.222 为 1 TiB，89.208.241.248 与 104.194.94.233 各为 2 TiB，上海每月 22 日重置。后两台以 `cycle.json` 的覆盖值为准。发布时应在节点设置填写这些月额，并按旧持久化用量校准本期补充已用；迁移不硬编码主机地址或擅改现有数据。

折线图按上海日期统计，支持近 7/30/90 天、节点和平台用户筛选。默认汇总全部 VPN 账号（含运维账号）；按平台用户筛选时汇总其全部历史绑定，包含管理员已删除的订阅。没有覆盖的日期保留缺口，不伪造为 0；节点部分不可用时明确标识，全部不可用返回错误。

节点使用独立每日历史表，首次升级从已有小时记录幂等回填，之后在唯一采样事务内增量累加。原生账号重置或删除不能清除该归档。升级前已清除的日志无法重建，跨日采样无法精确拆分时保留缺口标识。

## 用户页面

「VPN 订阅」展示开通资格、当前状态、已用/剩余/上下行流量、采样与同步时间、当前账期和下次重置时间。开通过程自动轮询；完成后可复制 Clash/Mihomo 和通用 Base64 地址。订阅链接含凭据，仅本人和有权限管理员可读，响应 `Cache-Control: no-store`。

采样尚未完成、节点断连或发现计量缺口时显示异常标识和最后成功数据，不能把 0 解释为已确认无用量。采样式限额存在检测延迟，不是逐字节零超额硬限额。轮换会同时更新 URL 和代理凭据，所有设备需要重新导入。

## 持久化与恢复

迁移 238 新增 `vpn_servers`、`vpn_subscriptions`、`vpn_operations`；239 增加删除墓碑和节点计量配置；240 增加独立 VPN 用户组和成员关系；241 增加下发标记、迁移状态及旧绑定历史；242 增加节点额度快照。保留既有订阅额度、历史绑定、用户余额与 AI 用量。节点额度统计使用现有 SQLite 数据，不新增节点表结构。

节点选择与预占使用 PostgreSQL 事务锁，迁移中的目标同样计入预占；用户和远端归属具有唯一约束。HTTP 请求在事务外执行。操作包含固定 UUID 与 owner_ref，通过租约及状态比较恢复；请求超时不换节点重复创建。旧租约、旧操作或旧采样回包不能覆盖更新结果。迁移源与途中已撤销的目标保留历史归属，用量图仍能查询；搬迁的额度扣减不重复计入目标节点的实际传输量。

服务每 5 秒处理操作与用户停用补偿；节点和订阅快照按约 30 秒间隔同步。字段 `sampled_at` 是 VPS 实际采样时间，`synced_at` 是平台成功读取时间，不能混用。

远端托管账户由集成 API 管理。Marzban 原生面板可以查看，但其原生写接口会拒绝托管账户；原生批量操作排除托管账户，避免破坏账期、归属及幂等记录。

## 接口

用户：`GET/POST /api/v1/vpn/subscription`，`POST /api/v1/vpn/subscription/refresh`。

管理员：`/api/v1/admin/vpn/servers`（列出、新增、修改、probe）、`/subscriptions`（列出、代开、修改、DELETE、revoke、refresh、retry）、`/summary`、`/groups`（GET/POST/PUT）、`PUT /users/:id/group`、`GET /traffic/daily`。每日查询必须提供 `start_date` 和 `end_date`，日期含两端且最多 93 天，可选 `server_id`、`user_id`。沿用现有管理员鉴权、用户 JWT、审计及面板限流；普通用户不能访问管理接口。

VPN 服务端合同见 VPS VPN 项目的 `docs/SUB2API_INTEGRATION.md`。创建/修改请求返回 202 只代表受理；必须等操作和运行态核验通过后展示可用链接。

`POST /subscriptions/:id/revoke` 必须提供 `{"target_server_id": 节点ID}`。列表可传 `sort_by=used_bytes|created_at`、`sort_order=asc|desc`，默认创建时间降序，未知用量排在末尾。节点端需具备 `allocated-quota-v1` 才能提供额度分配快照，跨节点迁移还需 `initial-usage-v1`；应先更新节点再部署平台。

## 验证与部署边界

本次完成了独立 PostgreSQL 下的并发/租约/归属测试、真实 Marzban/Xray HTTPS 及 Trojan 流量验证、平台 HTTP 与浏览器开通/管理流程。没有执行生产迁移或替换线上 VPN。

上线前应备份数据库和加密密钥，保留 `DASHBOARD_AGGREGATION_RETENTION_PRESERVE_HISTORICAL_DATA=true`，先升级并验收 VPN 节点，再部署 Sub2API。原有服务端 VPN 与 Sub2API 使用的客户端出口代理应分别核对切换，不要连带停用其他项目。

启用删除并重新开通后，同一用户会保留多份历史绑定，旧 0.3.0 不理解该结构，不能直接仅换回旧二进制作为回滚。发布时应保留支持删除墓碑的兼容回退版本；不得用发布前全库备份覆盖之后新增的真实流量和业务数据。
