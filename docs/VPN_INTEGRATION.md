# VPN 个人订阅接入

Sub2API 管理平台身份、订阅绑定、余额资格及节点分配；每台独立的 VPS VPN 1.1.0 实例运行 Marzban/Xray，负责实际代理、个人用量、每月账期和访问控制。

## 使用规则

- 默认每人每月 30 GiB（32212254720 bytes），上海时间每月 22 日 00:00 重置，不结转；月中创建获得完整当期额度。
- 自助申请时事务检查 `users.balance > 0`，不扣费、不冻结。该字段已是可用余额，不能再减 frozen_balance。之后余额为零不自动停用；管理员可以为零余额用户代开。
- 每用户全局一份绑定。创建中、失败待重试、禁用和超额均占名额；无用户侧删除重建、转绑或清零入口。
- 仅向启用、健康、最近两分钟确认可用的节点分配。排序依据为节点个人账号数加尚未在节点出现的本地预占；相同人数按最久未分配优先。运维账号由节点排除。
- 用户被平台禁用或软删除后，后台排队禁用 VPN；恢复平台用户不会自动恢复 VPN，管理员需重新启用。任何失败显示实际状态，不把数据库状态当成已阻断。

## 管理员配置

1. 先部署含集成模块和修订 Xray 的 VPS VPN 1.1.0 安装包，验证 HTTPS、`TROJAN_TLS`、个人采样和 `/api/integration/server`。
2. 在「VPN 管理 → 添加节点」填写名称、HTTPS Base URL、接入管理员用户名与密码。私有 CA 环境提供 PEM；公共受信任证书可留空。证书校验始终开启。
3. 节点检测通过后参与自动分配。管理员可搜索平台用户代开，查看汇总、流量、账期、失败原因，调整额度、启停、重试原操作、轮换订阅凭据。
4. 已绑定用户的节点不能修改 Base URL 迁移到另一个实例。新增实例应新建节点。编辑时密码留空保留原值；CA 字段省略保留，显式空字符串清除。

接入管理员凭据仅由后端保存，复用现有 AES-256-GCM 加密器，密钥来自稳定的 `TOTP_ENCRYPTION_KEY`。本功能不修改生产密钥；备份恢复必须保留原密钥。节点配置、管理响应和日志均不回显密码。登录 JWT 在内存缓存，401 后最多重新登录一次；不继承系统 HTTP 代理，不允许远端重定向。

## 用户页面

「VPN 订阅」展示开通资格、当前状态、已用/剩余/上下行流量、采样与同步时间、当前账期和下次重置时间。开通过程自动轮询；完成后可复制 Clash/Mihomo 和通用 Base64 地址。订阅链接含凭据，仅本人和有权限管理员可读，响应 `Cache-Control: no-store`。

采样尚未完成、节点断连或发现计量缺口时显示异常标识和最后成功数据，不能把 0 解释为已确认无用量。采样式限额存在检测延迟，不是逐字节零超额硬限额。轮换会同时更新 URL 和代理凭据，所有设备需要重新导入。

## 持久化与恢复

迁移 `238_vpn_subscriptions.sql` 只新增 `vpn_servers`、`vpn_subscriptions`、`vpn_operations`，不改已有用户余额和 AI 用量。

节点选择与预占使用 PostgreSQL 事务锁；用户和远端归属具有唯一约束。HTTP 请求在事务外执行。操作包含固定 UUID 与 owner_ref，通过租约领取和同一幂等请求恢复；请求超时不换节点重复创建。旧租约、旧操作或旧采样回包不能覆盖更新结果。失败操作由管理员重试原操作，不产生第二账号。

服务每 5 秒处理操作与用户停用补偿；节点和订阅快照按约 30 秒间隔同步。字段 `sampled_at` 是 VPS 实际采样时间，`synced_at` 是平台成功读取时间，不能混用。

远端托管账户由集成 API 管理。Marzban 原生面板可以查看，但其原生写接口会拒绝托管账户；原生批量操作排除托管账户，避免破坏账期、归属及幂等记录。

## 接口

用户：`GET/POST /api/v1/vpn/subscription`，`POST /api/v1/vpn/subscription/refresh`。

管理员：`/api/v1/admin/vpn/servers`（列出、新增、修改、probe）、`/subscriptions`（列出、代开、修改、revoke、refresh、retry）、`/summary`。沿用现有管理员鉴权、用户 JWT、审计及面板限流；普通用户不能访问管理接口。

VPN 服务端合同见 VPS VPN 项目的 `docs/SUB2API_INTEGRATION.md`。创建/修改请求返回 202 只代表受理；必须等操作和运行态核验通过后展示可用链接。

## 验证与部署边界

本次完成了独立 PostgreSQL 下的并发/租约/归属测试、真实 Marzban/Xray HTTPS 及 Trojan 流量验证、平台 HTTP 与浏览器开通/管理流程。没有执行生产迁移或替换线上 VPN。

上线前应备份数据库和加密密钥，保留 `DASHBOARD_AGGREGATION_RETENTION_PRESERVE_HISTORICAL_DATA=true`，先升级并验收 VPN 节点，再部署 Sub2API。原有服务端 VPN 与 Sub2API 使用的客户端出口代理应分别核对切换，不要连带停用其他项目。
